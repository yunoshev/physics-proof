# Task M8 — agent loop (with a minimal finish and a `run` command)

Spec: `SPEC.md` §2 (all principles), §3 "M8", §4 (rules of evidence), §7 (per-run cap). This is the module that turns
the tools into the product: Spark watches the clip and drives the tools until it can write `analysis.json`. Reuse every
done module; do not re-implement any of them:
`meta_client` (Spark, files, ledger), `video` (probe, read_frames, contact_sheet, duplicate_runs), `sam_tool` (M3),
`search_tool` (M4, with its classifier), `sandbox` (M5, `run_python`), `blocks` (M6, M6b), `mask_check` (M7),
`schema` (M9: `validate`, `combine`, `schema_doc`).

The page (M10) and the screenshot round of `finish` (M11) come later; here `finish` validates and writes the analysis.

## Build `physics_proof/agent.py`
- `run_analysis(video, run_dir, *, tier="contributor", cap_usd=2.0, max_turns=40, sam_frames=1500, searches=6,
  mask_checks=4, spark=None, resume=False) -> RunSummary`. `spark` is an injectable "next action" provider for tests;
  by default it is Spark through `MetaClient.respond`.
- **Blind start.** Copy the video to `run_dir/workspace/clip.mp4` (anonymised name), probe it (M2) and list duplicate
  runs; the agent sees only that file and that probe. Nothing else about the clip goes anywhere into the prompt.
- **Message 0:** the system prompt `config/prompts/agent_system.md` + generated parts (assembled at run time): role and
  goal (prove or disprove that the motion obeys physics, with an honest error bar; "undetermined" is a valid answer),
  the rules of evidence (SPEC §4, verbatim), the tools and their limits, the `blocks` documentation (generated from the
  docstrings of the public functions), `schema_doc()`, and the probe of the clip. Then the video itself
  (`video_part`, or the Files API when the file is larger than the inline limit).
- **Tools** (native tool calling, strict schemas, `tool_choice` auto — check what `meta_client` supports):
  `video_info()`, `frames(frames, crop=null, label=null)` → a contact sheet image of up to 24 frames,
  `sam(phrase, start, stop)`, `mask_check(file, object, frames, claim)`, `search(query)`, `python(code)` (M5 sandbox in
  the run workspace, `import blocks` available; returns stdout, stderr and the newest images),
  `finish(analysis_file, page_texts)`.
  Exactly one tool call per turn: if Spark returns several, run the first and say so; if it returns text without a
  tool call, answer "call exactly one tool" (this counts as a turn). A malformed call gets a readable error and the run
  continues.
- **Minimal `finish`:** load the JSON from the workspace, `schema.validate` (issues go back to Spark with their paths),
  check the mask-check gate (at least one check on the mask used as the size reference — `MaskCheck.has_check`),
  recompute every verdict with `blocks.decide` and `overall` with `combine`, write `run_dir/analysis.json`. The first
  successful finish ends the run.
- **Context:** keep the full conversation as an input list (not `previous_response_id`), so old images can be pruned:
  images older than the last two tool results are replaced by a one-line note; long tool texts are truncated with a
  note. Reuse the prefix unchanged between turns so the provider cache works.
- **Budgets enforced in code:** turns, SAM frames, searches, mask checks, and dollars. The dollar cap is checked
  **before every call**, including the calls tools make (SAM, search, classifier, mask check) — share one budget object.
  Near a limit, Spark is told so and asked to `finish` with what it has; at the limit the run ends as
  "undetermined: budget" with a valid summary.
- **Logs:** `run_dir/turns/NN.json` (Spark's text, the tool call, arguments, the full tool result, image paths, cost,
  cumulative cost), `run_dir/conversation.jsonl`, `run_dir/summary.json` (status, turns, SAM calls/frames, searches,
  mask checks, cost, wall time, analysis path, tier, model).
- **Resume:** `resume=True` replays saved turns into the conversation without calling anything and continues from the
  next turn.

## Build a `run` command
`python -m physics_proof run <video> [--tag TAG] [--tier contributor|standard] [--cap-usd 2] [--turns 40] [--resume]`
→ creates `runs/<date>-<tag>/` (git-ignored), runs, prints the summary and the analysis path. (The full CLI is M12.)

## Probes (tests)
Offline, with a scripted fake Spark that replays a fixed list of tool calls, SAM and search served from fixtures:
1. A full run on `tests/fixtures/sam_clip.mp4` (or a new synthetic ball-toss clip) ends with a valid `analysis.json`
   and a complete `summary.json`; the turn files hold every tool result.
2. A malformed tool call and a text-only answer each get a readable reply, and the run continues.
3. `finish` with a schema error returns the paths to Spark; `finish` without a mask check is refused.
4. The dollar cap stops a run mid-way with status "undetermined: budget" (fake costs).
5. Kill-and-resume reproduces the same turn files.
6. **Blindness:** the assembled system prompt for a clip named `apollo16_moon_jump.mp4` contains neither the file name
   nor any of: apollo, lunar module, singapore, red bull, marina bay, tiktok, salute, stunt; the clip is `clip.mp4`.
7. Image pruning keeps only the last two tool results' images.
API (`-m api`, ≤ $0.05): a real run on the synthetic clip with `--turns 4` reaches at least two tool calls and writes
turn files with costs that match the ledger.
