## Probes covered
1. Frame-accurate cut: on a 70-frame digit clip (M2 style), `run(...,30,60)`
   sent a 30-frame cut whose frame 0 matches digit-30 PNG (MAD < 5); saved
   masks carry frames 30..59.
2. Cache: repeat call makes no client call (`calls == 1`, `cached`, billed 0);
   sub-range 40..50 after 30..60 makes no call and its masks equal the
   cached slice rows 10:20 exactly. Key is full sha256 + phrase + range.
3. Budget: `budget_frames=100`, 60-frame then 50-frame (other phrase) call →
   second raises one-line `SamBudgetError` (a `RuntimeError`), no client call.
4. Result: npz round-trips via `blocks.load_masks`; sheet PNG exists; each
   object's summary bbox equals the union bbox recomputed from its masks;
   planted swap (two squares exchange at cut frame 5) reports frame 35 in
   `identity_swaps`; `text()` ≤ 1500 chars and notes the 50-frame minimum.
5. Phrases: `""`, `"a b c d e"`, `"car; rm -rf"`, `"red_square"`, `"a!"` raise
   `ValueError` with no client call; 1–4 words of letters/spaces/hyphens pass.
API (`-m api`, 1 call): `run("red square", 2, 8)` on `sam_clip.mp4` → masks
on frames 2..7, `frames_billed == 50`, ledger `sam` line written; repeat call
cached with no new ledger lines. Cost $0.010000 (50 × $0.20/1k).

## Notes
- Cut uses `select='between(n,start,stop-1)'` + re-encode (never `-ss`); the
  cut file is deleted even on API failure. `frames_billed = max(n, 50)` and
  the minimum is noted in `text()`.
- SAM string ids map to ints (`int()` or sorted order); cache stores the same
  npz schema as the workspace file under `cache/sam/` (git-ignored).
- `identity_swaps`: centroid jump between neighbouring present frames larger
  than the earlier frame's bbox diagonal; the later frame is reported.
