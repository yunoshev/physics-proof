# Task M10 — the frozen player, `build`, and a local gallery

Spec: `SPEC.md` §1 (what the page shows), §3 "M10", "M11" (page part), "M12" (`build`), "M13" (gallery part only, no
publishing yet). Read three real analyses first: `runs/2026-10-27-moonb-r2/analysis.json`,
`runs/2026-10-27-moona-r3/analysis.json`, `runs/2026-10-27-wallrun-r2/analysis.json` (with their `workspace/` and
`summary.json`). The page must work for all three: an image-frame flight (Moon) and a wall segment with a moving camera
(track in reference units).

Why: this page is what judges and viewers see. It must make the proof feel obvious: the video, the measurement drawn
on it, the numbers step by step, and a verdict anyone can read.

## Build
1. `player/` — one frozen template (`index.html` + `player.js` + `player.css`, no framework, no build step; fonts from
   Google Fonts allowed; everything else inline/local). Per analysis only the data and the video change. The analysis is
   embedded as `<script type="application/json" id="analysis">`. Record the template hash in `player/HASH`.
2. Page structure (English): a header with the verdict in plain words (e.g. "Physically impossible", "Moon gravity",
   "Slowed down ×1.46") and the key number; a sticky video with a canvas overlay; a step list the viewer walks through,
   each step seeking the video and drawing its overlay:
   1. **First look** — what the agent saw before measuring (`first_look`), clip facts (fps, frames, duplicates).
   2. **Reference** — each reference card: name, extent, size, source link and the verbatim quote, source type, the
      mask-check verdict and what the mask covers, with the mask-check sheet image.
   3. **Scale** — the scale bar on the reference frame; the second reference and how well they agree.
   4. **Motion** — for each segment: takeoff/start → apex → end with auto-pause; the tracked point and its trail; the
      fitted curve; the ghost ("where gravity would put it") as a second curve; a live h(t) chart (inline SVG) with
      measured points, fit and ghost, in metres.
   5. **Clock** — the time-rate check (`timescale`) and what a retime would imply (from `overall.text`).
   6. **Error budget** — horizontal bars.
   7. **Verdict** — g ± error on a scale with every hypothesis marked (Earth, Moon, …), the `overall` text.
   8. **How this was made** — model, turns, SAM frames, searches, mask checks, cost in USD, wall time (from
      `summary.json`), and a link to the run log.
   Controls: play/pause, frame step ±1, jump to each step, URL parameters `frame=` and `step=`.
3. Drawing: mask outlines from `masks` spans; the track from `track.points` — for `unit: px` directly; for `unit: ref`
   convert with `scale.frame_of_reference` when pixel positions are not stored, and add an optional `px: [x, y]` per
   track point to the schema (document it in `schema_doc()`; the agent should write it from now on). If a run lacks what
   a step needs, the step says so in one line instead of breaking.
4. `python -m physics_proof build <run_dir> [--out site/<slug>]` → `site/<slug>/index.html`, `clip.mp4` (copied),
   the images the page uses (copied, small), and recomputes every verdict and `overall` with the current `blocks.decide`
   and `schema.combine` (print what changed). `site/` is git-ignored for now.
5. `python -m physics_proof gallery` → `site/index.html`: one card per built analysis (a poster frame extracted from the
   clip, the verdict label, one line of text, cost), linking to the page.
6. `scripts/screens.py site/<slug>` — maintainer-run (headless Chrome at
   `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`, `--headless=new --screenshot`): screenshots of each
   step via `?step=N`, saved under `site/<slug>/screens/`. You may not be able to run Chrome in your environment; write
   it so that it fails with a clear message, and test the URL-to-step logic without Chrome.

## Design
Clean and confident, made to be watched: generous whitespace, one accent colour, readable at phone width, light and dark
via `prefers-color-scheme`. Numbers in a monospaced figure style with units. The verdict colour: green for a world that
fits, amber for retimed, red for impossible, grey for undetermined. No stock imagery, no emoji.

## Probes (tests, offline)
- `build` on the three runs above produces pages whose embedded JSON validates; the page without the video is ≤ 1 MB.
- The template files do not change between the three builds (hash).
- Every text string on the page can be overridden from `page_texts`.
- A missing optional section (no `timescale`, no ghost) renders the step's one-line notice (test the JS logic with a
  small Node-free check, e.g. by testing the Python side that prepares the data, or by a pure-JS test runnable with the
  `node` binary if present; skip if absent).

## Done when
Offline tests pass; the three pages and the gallery build; `tasks/M10.report.md` written with the build commands. The
maintainer opens the pages in a browser and runs `scripts/screens.py`.
