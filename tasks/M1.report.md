# M1 report — Meta API client and cost ledger

## Built
- `pyproject.toml` (httpx, numpy, meta-sam-parser; pytest in dev group), `physics_proof/` package.
- `config/prices.json` — prices from the task, not in code.
- `physics_proof/config.py` — Settings (base URL, contributor model, effort low,
  max tokens 4096, price/ledger paths), env-overridable (`META_*`).
- `physics_proof/ledger.py` — `Usage`, `compute_cost_usd`, `Ledger(run, global)` (one
  JSON line per call to both files), `Ledger.total`. Cached tokens are a subset of
  input tokens: no discount, no double count.
- `physics_proof/meta_client.py` — `MetaClient.respond` (streaming, strict-schema
  tools, `web_search`, reasoning effort), `text/image/video_part` (data URL ≤50 MB,
  else Files upload), `upload_file`/`delete_file`, `sam_video` (upload → stream →
  `meta-sam-parser` decode → full-frame bool masks → delete even on error). Retries
  429/5xx ×3 with `Retry-After`; 402 → single-line `BillingError` naming the Billing
  page; other 4xx → `ApiError(status, message, param)`; bad stream → `StreamError`.
- `scripts/record_fixtures.py` + `tests/fixtures/`: `sam_clip.mp4` (10f, 256×256,
  red square via lavfi `color`+`overlay`), `spark_text.sse`, `spark_tool.sse`,
  `sam_red_square.sse`, `sam_manifest.json`.

## Probes
1. Fake 402 → `BillingError`, exactly 1 request. 2. 429→200 succeeds after 1 retry;
   4×500 → `ApiError` after 3 attempts. 3. Truncated/garbage SSE → `StreamError`.
   4. Fixtures parse: text non-empty; tool turn = 1 call `get_time({city: Paris})`.
   5. SAM decode: 10/10 frames, bool `(256,256)` masks, non-empty, inside boxes.
   6. Ledger: 8 hand-computed cases match; both files total identically. 7. Sentinel
   key in env appears in no run file, log, or exception. API: Spark `completed`
   + ledger line; SAM 10/10 frames masked, `frames_processed` 50 > 0.

## Test output
- `uv run pytest`: 25 passed, 2 skipped (api). `uv run pytest -m api`: 2 passed.

## Could not do (and why)
- **Fixture budget `< $0.01` missed: total `$0.01016`.** The API reports
  `video_frames_processed = 50` for 10-frame (and 5-frame, 0.5–1 s) clips — a
  50-frame processing floor. So the SAM fixture call costs exactly
  50×$0.20/1000 = `$0.01000` under the price table, and the two Spark calls add
  `$0.00016`. No lever exists (cheapest tier/effort already). The script keeps the
  hard cap and exits nonzero; fixtures are saved before the check. Recommend:
  raise the fixture cap to $0.02, or rule that `frames` bills input frames.
