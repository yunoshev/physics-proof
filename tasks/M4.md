# Task M4 — Search tool with a blindness filter

Spec: `SPEC.md` §3 "M4. Search tool" and §2 Principle 7 (blindness). Build only this module and its tests. Reuse
`physics_proof/meta_client.py` (`MetaClient.respond` with `web_search=True`, `json_schema`) and the ledger.

Why: the analysis agent may look up **reference facts** (how big a known object is, physical constants, what a piece of
equipment is) but must never be handed **the answer** (how high/long/fast the filmed event was, or whether the clip is
real, slowed or fake). The filter is what keeps the measurement honest.

## Build `physics_proof/search_tool.py`
- `SearchTool(client, workspace, *, limit=6)` and `SearchTool.run(query) -> SearchResult`, the agent's `search(query)`:
  1. `check_query(query) -> (allowed, reason)` — refuse **before** any API call when the query asks for the filmed
     event's own quantities (height, distance, hang/air time, speed, g of *this* jump/fall/flight/stunt/record) or for
     authenticity (real, fake, hoax, staged, CGI, AI-generated, slowed, slow motion, sped up, playback speed, frame rate
     of the footage, debunk, fact-check). Word lists + regular expressions, case-insensitive; keep them in
     `config/blindness.json`, not in code.
  2. A separate Spark call with `web_search`, a short instruction ("return facts with their source URL and a verbatim
     quote; no opinions") and a strict JSON schema `{facts: [{text, source_url, quote}]}` (≤ 5 facts).
  3. `filter_answer(facts) -> (kept, cut)` — drop any fact whose text or quote trips the same rules (e.g. a sentence that
     states the event's height or calls it fake); record every cut.
  4. Per-run limit (`limit`); the 7th call is refused with a clear message and no API call.
  5. Log every query, refusal, cut, the sources and the cost as JSON lines in `workspace/search.jsonl`.
  `SearchResult`: `allowed`, `reason`, `facts`, `cut`, `cost_usd`, and `text()` (compact, ≤ 1 500 characters, with the
  source URL of each fact).

   - **allowed:** "Apollo A7L spacesuit height and mass" · "Apollo PLSS backpack dimensions" · "Lamborghini Aventador

     gravity value in m/s^2" · "surface gravity of the Moon" · "inflatable blob airbag length" · "what is the box on the
     back of an Apollo astronaut" · "12 ft trampoline diameter in metres"
   - **refused:** "how high did the astronaut jump in the Apollo 16 salute" · "Apollo 16 jump salute hang time" · "is the
     moon landing footage slowed down" · "blobbing world record height" · "how long was he in the air" · "was this video
     faked" · "IShowSpeed Lamborghini jump real or fake" · "debunk moon landing slow motion" · "speed of the car in this
     viral video" · "frame rate of the original Apollo 16 broadcast"
2. `filter_answer` on planted facts: a fact "The jump reached 0.5 m" (event quantity) and "Experts say the clip is
   fake" are cut and logged; "The PLSS is 26 inches tall" is kept.
3. The limit: with `limit=2`, the third call is refused without calling the client (fake client counts calls).
4. The log file has one line per call with query, decision, cut count and cost.
API (`-m api`, < $0.01): one real query "standard gravity value in m/s^2" returns at least one fact with a source URL
and a quote that appears in the text; the ledger has a line with `searches = 1`.
