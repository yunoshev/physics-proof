# Physics Proof

**Drop in any video; it asks what is worth proving, measures it, and shows every step on the footage.**

Live: [https://yunoshev.github.io/physics-proof/](https://yunoshev.github.io/physics-proof/) — press Play to watch each analysis play out on the footage.

See it work: [Apollo 16 salute hop — Moon, g = 1.65 ± 0.10 m/s²](https://yunoshev.github.io/physics-proof/moon/) · [Apollo 16 salute hop, sped up ×2.46 (a test fake made by us from the NASA clip) — retimed ×2.43, g = 9.58 ± 0.65 m/s²](https://yunoshev.github.io/physics-proof/moon-fast/) · [IShowSpeed jumps over a Lamborghini — Earth, g = 10.65 ± 1.11 m/s²](https://yunoshev.github.io/physics-proof/speed/)

Demo video: [watch](https://www.youtube.com/watch?v=xGzqiPTDuhI)

**One system for any clip — $0.36 per clip**

It is one general system, not a script for one clip; nothing in the code is tuned to a particular video. For each clip Muse Spark works out from the frames what a viewer would doubt, finds objects of known size and their sourced sizes, and plans the checks: a free flight against the world's gravity, a size or speed against a sourced human range, a step rate against a natural clock. During the hackathon it was verified end to end on a limited set of clips, listed under Results.

Average cost per clip: **$0.36** = Muse Spark $0.24 + SAM 3.1 $0.11 + web search $0.01 (average of 53 live runs, 1–3 November 2026).

**Limits.** This is a working concept, not yet proven on every kind of clip. It reached right verdicts end to end on three clips: the Apollo clip, our sped-up copy and a handheld street jump. The street jump needed several runs and two new general rules: the agent first took a hand on the car from small frames without checking its own masks, and the jumper's tucked legs needed a wider error budget. With both rules in the briefs, the regenerated code measured the flight. A new kind of clip may still need new rules.

**Rebuilt from text — $0.3390 for a full rebuild**

No hand-written code: the 15 briefs are the only human-written part (the owner's requests, turned into briefs by Muse Wonder). Muse Spark generates every part through Muse Code, one part at a time (`tools/dev_loop --part NN`). The full test suite checks each generation, and a live run that went wrong changed the brief, not the code.

A full rebuild of all 13 parts by Muse Spark: **$0.3390** (the last generation of each part, section 4).

## 1. What it is

A video goes in, and a player page with a physics verdict comes out.
Every analysis ends in one of three states: the motion fits one
scene-allowed world at native speed, it fits only under a corroborated
retiming, or no world fits and the result says why (physically
impossible, or undetermined with a reason).

## 2. How it was built

Built during the Meta hackathon, from 2026-10-27. The briefs in `brief/`
are the only human-written part (the owner's requests, turned into briefs
by Muse Wonder). All code, tests and the player are
generated by Muse Spark through Muse Code (`tools/dev_loop`). Every
analysis run is done by Muse Spark with SAM 3.1 through the Meta Model API.

## 3. Run one video

```sh
uv run python -m src.cli <video> --runs-dir runs
```

It needs `META_API_KEY` in the environment. The run writes
`runs/<run-id>/`: the anonymised clip and timing in `input/`, scratch in
`workspace/`, tool outputs in `artifacts/`, the operator-only log in
`logs/`, and the validated `result.json` plus `summary.json`.
Then build its player page with `src.pagebuild.build_page`:

```sh
uv run python -c "from src.pagebuild import build_page; build_page('runs/<run-id>/result.json', 'runs/<run-id>/input/clip.mp4', 'pages/<clip>')"
```
